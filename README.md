# 每日 AI 新闻助手 Agent

用户设置关注话题和关键词后，Agent 自主选择工具获取和筛选新闻，生成带原文链接的中文简报。简报保存到 SQLite，开启订阅后每日通过 SMTP 邮件推送。

这是本地作业演示项目，使用 Python 3.11+、FastAPI、原生前端和 OpenAI 官方接口。没有登录认证，默认只监听本机；不要直接开放到公网。

## 启动

1. 安装 Python 3.11 或更高版本。
2. 将 `.env.example` 复制为 `.env`，填写 `OPENAI_API_KEY`。`OPENAI_MODEL` 默认是 `gpt-4.1-mini`，可改为账号支持的 function calling 模型。
3. 运行 `sh start.sh`。如果系统默认 Python 较旧，运行 `PYTHON=python3.11 sh start.sh`。
4. 打开 http://127.0.0.1:8000，填写昵称、邮箱和订阅偏好，保存后点击「立即生成」。

启动脚本创建虚拟环境、安装依赖、初始化数据库并启动服务。不填写模型密钥也能打开页面和保存订阅，生成接口会明确提示缺少配置。修改 `.env` 后重启服务。

`requirements.txt` 列出直接依赖，`requirements.lock.txt` 锁定本次验证版本；启动脚本及 Docker 使用锁定版本。

可选容器启动：准备好 `.env` 后执行 `docker compose up --build -d`。数据保存在宿主机 `data/`，容器重启不会清空历史。端口绑定到本机，服务使用单个 worker。

## 邮件和每日执行

设置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`，需要认证时填写 `SMTP_USER`、`SMTP_PASSWORD`。`SMTP_SECURITY=starttls` 通常配合 587 端口；`SMTP_SECURITY=ssl` 通常配合 465 端口。按邮箱服务商要求使用授权码，不要把密码提交 Git。

发送时间固定按北京时间解释，默认 09:00。开启订阅后，后台每分钟检查一次；服务启动时补跑当天已到期且未创建过的每日任务。服务必须持续运行，本地关机期间不会执行，不补发以前日期。缺少模型密钥时调度器等待配置，不占用当天任务记录。

手动「立即生成」只保存简报，不自动发送邮件。生成成功后可点击「发送这份简报」。没有 SMTP 配置时显示「未配置邮件」。邮件生成、投递及错误状态独立记录；SMTP 明确接受邮件后标记已发送，这不等同于收件箱实际到达。

明确的临时 SMTP 错误最多尝试三次，永久拒绝停止。发送过程中断开且无法判断服务端是否已接收时，标记「投递结果未知」，不自动重发。已发送、失败或未知的投递记录不重复发送，避免误发；需要重新生成另一份简报才会产生新的投递记录。

## 模型如何决定工具调用

核心位于 `app/agent.py`：

1. 将工具定义和订阅偏好发送到 OpenAI，`tool_choice=auto`。
2. 读取模型返回的 `tool_calls`，校验权限后执行模型选择的工具。
3. 将实际结果作为带 `tool_call_id` 的工具消息返回模型。
4. 重复调用，直到模型输出最终 JSON，或达到运行上限。

工具包括 `list_dir(path)`、`read_file(path)`、`search_content(keyword, dir)`、`write_file(path, content)`、`bash(command)`、`fetch_news(source_ids, since)`。后端没有预设“列目录 → 读文件 → 搜索 → 写文件”的顺序，也不要求每次使用所有工具。获取新闻与引用校验是结果约束，工具顺序由模型决定。模型最终输出后，后端验证、入库和推送属于可靠性处理。

每次任务建立独立工作目录。目录里提供偏好和最近已推荐链接，模型可写草稿。限制为 15 轮、30 次工具调用、240 秒运行窗口；超限和工具错误记录到历史。前端「工具调用记录」显示工具名称、参数、结果和耗时，不显示模型内部思考。

协议依据：[OpenAI function calling 官方文档](https://developers.openai.com/api/docs/guides/function-calling)。后端启动和后台任务生命周期依据：[FastAPI lifespan 官方文档](https://fastapi.tiangolo.com/advanced/events/)。

## 来源、筛选和安全边界

`sources.json` 管理 Hugging Face Blog、Google Research Blog、TechCrunch AI 的 RSS 地址。源内容可能变化或不可用，可修改配置后重启。

默认读取最近 24 小时内有明确发布时间的新闻，跳过未来时间、没有时间的条目和近七天已经入选的链接；最多生成八条。模型按话题和关键词判断相关性，后端额外检查排除关键词、重复引用和链接来源。话题筛选属于模型判断，不能保证语义相关性始终准确。

简报基于 RSS 摘要，不声称读取全文。没有匹配内容时保存空简报；没有任何成功获取的来源时任务失败。原文链接、来源和发布时间必须来自实际获取的材料，不能由模型凭空编造。摘要事实仍需读者核对原文。

文件工具只访问当前任务工作目录，拒绝越界和符号链接。`bash` 通过无 shell 的子进程执行，仅允许 `cat`、`wc`、`head`、`tail`；不允许管道、重定向、任意脚本和网络请求，不继承 API Key 等环境变量。Windows 没有这些命令时工具会返回错误，文件工具仍可正常使用；推荐 macOS、Linux 或 Docker 演示。

新闻和偏好按不可信数据处理。模型仅收到订阅主题、关键词、排除词和新闻材料；昵称、邮箱、SMTP 密码不会放入模型任务或文件工作目录。偏好和新闻摘要会发送到 OpenAI，文件和工具日志保存在本机；不要在关键词中填写敏感信息。

`.env`、数据库、任务材料、虚拟环境和日志已加入 Git 忽略规则。浏览器对所有模型输出进行 HTML 转义，原文链接校验为 HTTP(S)，新窗口链接使用 `noopener noreferrer`。

## 数据库与接口

`migrations/001_initial.sql` 包含用户、运行记录、工具调用、新闻缓存和邮件投递表；`python -m app.db` 可单独初始化。用户表的 JSON profile 保存身份与订阅。每日任务键唯一，同一用户同时只能有一个运行任务。当前建表脚本可重复执行，schema 版本为 1；后续结构变更需要追加迁移。

接口文档：http://127.0.0.1:8000/docs。

| 接口 | 功能 |
| --- | --- |
| `GET /api/health` | 配置状态和来源 |
| `GET /api/users`、`POST /api/users` | 列出、创建演示用户 |
| `PUT /api/users/{user_id}` | 保存身份与订阅 |
| `POST /api/users/{user_id}/runs` | 异步生成，返回运行 ID |
| `GET /api/users/{user_id}/runs` | 最近 100 条历史 |
| `GET /api/users/{user_id}/runs/{run_id}` | 简报、状态和调用记录 |
| `POST /api/users/{user_id}/runs/{run_id}/send` | 投递已完成的简报 |

用户 ID 用于演示数据分组，没有认证能力。多 worker 或公开部署需要增加认证、持久任务队列和调度所有权；当前版本不支持该部署模式。任务资料暂不自动清理，长期运行需管理磁盘空间。

## 测试与现场演示

执行 `.venv/bin/python -m pytest -q`。测试使用固定新闻、模拟模型响应及模拟 SMTP，不消耗模型额度、不发送真实邮件，覆盖工具顺序、次数上限、引用验证、文件和命令边界、用户隔离、调度时间、重启恢复和投递状态。

没有有效密钥时，可运行 `.venv/bin/python scripts/seed_demo.py` 创建带醒目标记的离线示例。该脚本新增一个暂停订阅的演示用户及示例历史，不覆盖现有用户；示例不代表真实新闻或真实模型调用。

现场验收：

1. 配置真实 OpenAI 密钥，创建两名偏好不同的用户。
2. 分别立即生成，核对入选理由、来源链接和调用记录。新闻稀少时允许出现空结果。
3. 修改一名用户偏好后再次生成，核对筛选变化；近七天去重可能让结果减少。
4. 配置 SMTP，使用自己明确指定的测试邮箱发送一份简报，核对邮箱实际接收。
5. 将启用订阅的发送时间设置为当前时间附近，保持服务运行，检查每日任务和投递记录。一天内同一用户只创建一份每日任务。

真实模型请求需要联网和有效额度，实际邮件到达需要有效 SMTP 和收件邮箱。模拟测试通过不能替代这两项验收。
